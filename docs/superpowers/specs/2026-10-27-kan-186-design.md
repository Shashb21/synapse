# KAN-186: complete Gantt claim selection

Spec authority: https://synapse21.atlassian.net/browse/KAN-186.

Typed claim queries must filter by workspace and claim type in SQL before applying their limit. Existing callers keep the default limit of 200. Gantt projection must explicitly request all workspace claims, without a larger arbitrary cap. A final save must project activities, validate their tactic bindings, and derive snapshot tactic IDs, counts, and labels from the same loaded claim set. Active validated undated tactics continue to count in the snapshot; draft, rejected, and merged claims retain their existing behavior.

Extend listClaims with explicit `limit: null` meaning unlimited. Keep its ordinary bounded default, rather than changing every consumer. Extract a private projection helper that accepts loaded claims so save-final can reuse the same complete set without a second claim read. Retain workspace isolation and existing error propagation and snapshot hashing.

Alternatives considered: resolving projected IDs alone would still silently omit older projection data; merely raising limits preserves the bug at a higher size. Pagination adds unnecessary coordination for this bounded-scope internal operation. A complete query fits the existing store and in-memory projection architecture. Material tradeoff: memory and query work grow with workspace size.

Verify with real PostgreSQL/Vitest regressions for typed limiting and workspace isolation, >200 mixed claims with an older dated validated tactic, and >500 claims with complete activities, labels, IDs and counts. No UI or unrelated coverage-pair changes.
