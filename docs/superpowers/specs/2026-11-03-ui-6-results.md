# UI-6 — Results and optional evaluation

Authority: https://synapse21.atlassian.net/browse/UI-6 (fetched 2026-11-03).

The owner wants generated output and meaningful generation status first, followed by optional evaluation, saved run history and comparison. Preserve owner authorization, experiment isolation, document identities, immutable run/profile history, concurrency and spending safeguards. No pipeline/scoring algorithm changes or paid calls.

Acceptance: distinguish generation and evaluation progress/failure/completion/absence and not-applicable sections; readable gap/tactic/matching/split output; plain current/outdated reasons and relevant explicit rerun/re-evaluation action; explain gold standards as expected answers, profiles as evaluation criteria, evaluators as separate from generation. Separate factual checks, reviewed reference measures, provisional AI assessments and unscored results. Missing references and empty denominators remain unscored. Keep relevance/design fit/delivered evidence coverage distinct and never imply human approval or blended accuracy. Expand advanced settings, criteria, identities, raw traces and call metadata; retain visible errors and cost uncertainty. Saved run/evaluation reopening must display frozen settings/identities. Comparison puts document/reference/scoring differences before quality, retaining compatibility and single-trial limitations. Distinguish estimates, usage costs, reported spend. Include usable loading/empty/error states and accessible keyboard, headings, focus, desktop/mobile/200% zoom.

Use scripted browser outputs with isolated persistence, targeted behavior tests, lint and TypeScript. Verify successful outputs, generation/evaluation failures, optional evaluation with/without compatible references, outdated results, frozen history and incompatible comparison. No paid model calls.

Approach: extend existing Development presentation components, leaving persistence and scoring contracts unchanged. Native details controls provide progressive disclosure and keyboard access. Reuse server freshness metadata rather than invent freshness in the UI.

Ticket owner branch instruction: base and PR target updated-dev-environment-ui. The invoking workflow authorizes implementation and publication without routine confirmation.
