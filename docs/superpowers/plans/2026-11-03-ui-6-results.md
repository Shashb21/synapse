# UI-6 Results Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make generated results and optional evaluations understandable without changing experiment semantics.
**Architecture:** Extend the existing Development React presentation components and use existing saved execution/evaluation data and freshness metadata. Keep mutable editor configuration distinct from frozen history.
**Tech Stack:** Next.js 16, React, TypeScript, Vitest, Playwright.
**Spec:** docs/superpowers/specs/2026-11-03-ui-6-results.md and live Jira UI-6.

## Global Constraints

- Preserve experiment isolation, authorization, fixed document identities, frozen execution history, concurrency protection and spending safeguards.
- Do not alter customer workspaces, shared model routing, pipeline algorithms or human-review semantics.
- Missing references and empty denominators never appear as zero or perfect scores.
- No UI wording implies automatic human approval or a blended overall accuracy score.
- No paid model calls. Changes are presentation only; frozen records/profile versions remain immutable.
- Work only in /private/tmp/synapse-ui6. Share the codebase and preserve others' edits. No nested subagents. Controller owns git commits/pushes/PRs.

## Review Focus

- Queued/running/failed generations must not claim generated output exists; evaluation failure must not imply generation failure.
- Unknown freshness must not claim current; changed dependencies get plain explanations and explicit actions.
- Reopened historical evaluations display frozen settings regardless of current editor selection.
- Absent/incompatible references and zero denominators remain unscored; no mixed accuracy claim.
- Long saved content/identifiers and expanded controls remain usable on mobile and at 200% zoom; untrusted output stays escaped text.
