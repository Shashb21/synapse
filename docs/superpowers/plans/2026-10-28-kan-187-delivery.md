## Implemented behavior

- Each extraction request processes at most 80 ordered blocks and reports total, processed count, partial/complete status and continuation.
- Durable checkpoints bind workspace, source, ordered content snapshot, reference pack, page position and extraction kind. Continuations cannot skip unsaved pages; stale content requires restart.
- Claims, provenance and page-kind completion commit in one transaction. A unique checkpoint arbitrates concurrent requests; retries reuse saved work without relying on model IDs or wording.
- Each saved claim requires a valid quote from its own batch. Existing merge/status work still runs after extraction, preserving its human-decision protections.
- The source UI shows progress and Continue/Retry/Restart, retains selected extraction kinds and failed continuation, and handles transport and malformed JSON failures through existing postJson behavior.
- Review fix: extraction saves and parse mutations acquire the same source-row lock before reading current blocks/dependent quotes and writing. Edit, split, merge, delete, add, restore and reparse now run their coupled writes and audit in one transaction. Model generation remains outside the lock. The real PostgreSQL trigger regression pauses claim insertion after validation, races a human edit, then verifies that edit waits and refuses to orphan the newly committed quote.
