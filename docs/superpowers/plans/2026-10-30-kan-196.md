# KAN-196 Session context and developer tools implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Separate local demo sign-in from everyday owner controls without changing authentication or authorization.

**Architecture:** Reuse SessionPanel and its existing POST/redirect behavior. Render its compact identity and genuine session actions before the availability summary. Native details/summary contains the existing unsigned development-only form, collapsed by default. Remove the capability inventory and role explanation from this operational surface.

**Tech Stack:** Next.js, React, TypeScript, Vitest with React DOM, Playwright.

**Spec:** Jira KAN-196, retrieved 2026-10-30: https://synapse21.atlassian.net/browse/KAN-196 . Its description and acceptance criteria are authoritative.

## Design

Keep the actor name, plan role and explicit signed-in/unsigned status visible. Identify a demo session from identity.session.provider_id === "demo", because identity.demo only means no identity providers are configured. Pass a boolean rather than a session object to the browser. Preserve the current signed-out demo-mode signal independently. The owner status comes only from confirmed owner access. Unknown identity keeps recovery copy and cannot invent a demo or signed-in session. Genuine sign-in/sign-out stays outside the disclosure. Developer tools uses the existing non-production guard and unsigned-only form condition; no new account switching privileges. The form stacks at narrow widths.

Alternatives considered: a new settings route adds navigation and is excluded by the ticket; merely collapsing the whole session panel would hide required identity/recovery. The ticket already specifies this design; execute without an additional design approval gate.

- Preserve genuine sign-in and sign-out actions and configuration/identity recovery.
- Use the existing visual design, native accessible disclosure and visible keyboard focus; form must fit narrow widths.

## Review Focus
- Authenticated real user with no configured identity providers must not be labeled a demo session.
- Authenticated demo user with configured identity providers must still be labeled demo.
- Production never includes demo form/disclosure, while genuine signed-out sign-in remains available.
- Identity read failure remains unknown and preserves configuration recovery.
- Keyboard disclosure, mobile form usability, redirects and network error recovery remain functional.
