# KAN-202 experiment execution implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Execute the bounded tasks and review each.

**Goal:** Execute all four real pipeline sections in isolated, immutable Development attempts, with Standard and Single pass modes, local routes and durable dispatch.
**Architecture:** Reuse actual S2/S3/S4/S6 modules through frozen replay contexts, never customer runStage or Accuracy substitutes. Intercept explicit role completions for durable request/reply checkpoints; replay only saved replies when advancing a suspended stage. PostgreSQL owns conflicting-run protection and one-time dispatch claims. A deployment-supported scheduled worker owns progression independently of browsers.
**Tech Stack:** Next.js 16, TypeScript, PostgreSQL/Drizzle, Zod, Vitest, Playwright.
**Spec:** KAN-202 and approved KAN-199 on https://synapse21.atlassian.net; architecture trace /private/tmp/kan202-architecture.md; existing docs/development/experiment-contract.md.

## Global Constraints

- All generated output is experiment-local and explicitly unreviewed. No customer writes, human approvals, shared route changes or gold/reference inputs to generation roles.
- Standard preserves production exchange count and judges. Single pass uses real initial proposal and structural/reference checks, omitting critique/revision/internal acceptance. Distinguish structural validity from acceptance.
- Per-stage route defaults with explicit proposer/critic/reviser/internal_judge overrides; separate evaluator selection for later evaluation ticket. Validate provider model capability/availability/settings, preserve requested/actual routes and explicit fallback.
- Use source snapshots only. S2/S3 feed local domain state, S4 links those outputs with real dimensions and reference validation, S6 consumes justified partial mappings, preserves scope, never applies splits. No eligible partial gaps means not_applicable.
- Run All freezes current config and creates fresh section attempts in order S2,S3,S4,S6, preserving independent success. Individual runs bind exact current successful prerequisites; stale or failed newer prerequisites cannot silently reuse older outputs.
- Durable DB claim from first API execution. Persist dispatch before send; never retry uncertain billed calls automatically. Persist prior replies and resumed work. No open-browser dependency or fire-and-forget Promise delivery.
- Existing AI master/section switches and provider/cost policies apply, including dispatch-time checks. No paid calls in tests. Unknown cost remains unknown. Dedicated KAN-206 owns experiment estimates/allowances UI.
- Owner authorization, bounded schemas, safe no-store errors, accessible actions. Additive tables only. PR targets KAN-200 under ticket-specific workflow, both remotes; leave open.
- Workers share the codebase, preserve others' edits, do not spawn agents, commit or push. Controller owns publication and review.

## Review Focus

- Standard production behavior stays unchanged when no experiment execution mode is supplied.
- Suspended real-stage replay cannot diverge silently: compare each replayed prompt/request identity and refuse mismatch.
- Dispatch crash or ambiguous network failure never causes provider resend; repeated worker delivery sends at most once.
- Changed sources/config or failed upstream rerun blocks stale downstream reuse, while historical output remains inspectable.
- Relevant mappings need supplied references even where production validates at the commit boundary; replay must enforce equivalent integrity.
