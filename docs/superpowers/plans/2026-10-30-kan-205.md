# KAN-205 section results and saved experiment comparison Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development task by task.

**Goal:** Inspect all four saved section outputs and compare immutable one-trial experiments without misleading quality claims.

**Architecture:** Extend existing owner-only Development execution/evaluation storage and controls. Compute comparison metadata from saved manifests; reuse evaluation controls and generation API. Keep raw evidence available alongside structured output.

**Tech Stack:** Next.js 16, React, TypeScript, Zod, Vitest, Playwright.

**Spec:** https://synapse21.atlassian.net/browse/KAN-205 and approved KAN-199 / KAN-200 scope. Parent integration branch KAN-200 already includes KAN-203/204. Baseline 636ef46.

## Global Constraints

- Four sections: gap_extraction, tactic_extraction, matching_coverage, partial_splitting.
- Matching & coverage remains one generation action, with separately inspectable relevance, design fit and delivered evidence coverage assessments. A planned/relevant tactic is not proof of delivered evidence.
- Splitting assessments cover supported addressed scope, complete remaining need, non-overlap, parent-meaning preservation and valid references. No eligible partial gap is not applicable, not a perfect score.
- Reference measures require compatible section references; factual checks and provisional AI judgments remain available without gold. Display omissions/duplicates/denominators and provisional status without fabricated human review.
- Generation and evaluation states remain separate. Preserve rejected/failed evidence and existing independent profile/evaluator reevaluation of exact saved outputs; reevaluation never regenerates.
- Compare saved executions across experiments owned by the authorized owner. Identify document/reference/evaluator/profile/version differences; model and mode may intentionally vary, but differing inputs or rubrics prevent controlled quality comparison. Every execution is one trial; never claim statistical superiority.
- Safely render untrusted content as React text, bound and authorize API inputs before persistence access, link only existing owner-authorized trace routes. Unknown accounting remains unknown.
- No paid model calls, algorithm changes, customer/shared settings changes, new dependencies or merges. PR targets KAN-200, published to both configured remotes. Controller owns git/PR/Jira actions.

## Review Focus

- Missing legacy metadata or malformed output must display unavailable evidence without fabricated values or crashing.
- Different section/input/reference/profile bindings must not produce a controlled-comparison claim.
- Selecting another experiment/execution during a fetch must not publish stale comparison data or launch the wrong configuration.
- Copying historical settings must retain exact mode/routes, validate stale prerequisites, and require an explicit generation action.
- No eligible partial splitting may be scored as perfect or expose an enabled misleading evaluator action.
