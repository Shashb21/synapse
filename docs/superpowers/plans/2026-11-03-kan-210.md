# KAN-210 Development evaluation consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Retain historical benchmark/reference tools under Development without changing identities or duplicating existing workflows.
**Architecture:** Move pure benchmark/reference ownership and freeze its historical prompt/audit dependencies. Keep customer pipeline execution on existing Development implementations. Expose a small owner-only evaluation tools entry point.
**Tech Stack:** TypeScript, Next.js, Vitest, Playwright.
**Spec:** docs/superpowers/specs/2026-11-03-kan-210-design.md (implements Jira KAN-210).

## Global Constraints

- No Accuracy runtime/store dependencies in Development evaluation tools.
- Preserve benchmark command names, JSON/CSV formats, review rules, reference resolution and saved-run compatibility.
- Historical benchmark prompts and audit/scoring identities remain unchanged. Stop an incompatible move; never bless a changed hash.
- No automatic migration of records, no private artifact publication, no paid provider verification calls, no live configuration writes.
- Preserve existing owner authorization, isolation, evaluator-only references, immutable histories and AI-off controls.
- Existing real customer stages remain the only current-pipeline validation path.

## Review Focus

- A pre-move saved synthetic run must review/resume with zero provider or credential access after relocation.
- Audit functions use toString identities: bundler-dependent name changes must fail the frozen baseline guard.
- Reference loader paths and pack separation must survive the move.
- The new tools entry point must be owner-only and clearly mark historical scope.
- Existing model comparison/evaluation/cost workflows must preserve live settings and safety checks.
