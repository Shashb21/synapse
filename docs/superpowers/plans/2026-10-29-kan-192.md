# KAN-192 configuration recovery implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Show configuration read failures honestly and let the owner recover safely.
**Architecture:** The server control-panel loader owns independent read results. Existing panels consume explicit availability; a small client refresh control announces pending and server-confirmed results while retaining route drafts across failed retries. Route-preview presentation uses safe, explicit results without changing runtime routing policy.
**Tech Stack:** Next.js 16.3, React 19, TypeScript, Vitest, Playwright.
**Spec:** https://synapse21.atlassian.net/browse/KAN-192 (current description fetched 2026-10-29).

## Global Constraints

- Preserve the earlier uncommitted KAN-109 improvements copied into this worktree. The original checkout must remain untouched.
- Preserve owner authorization, server-side validation, provider policy and API-key secrecy.
- Do not redesign database infrastructure or change runtime routing/fallback policy.
- Unknown data must never appear as saved defaults or intentional AI-off state.
- Partial failures must preserve independently confirmed settings and their safe operations.
- Raw queries, parameters, secrets and stack traces must never appear in page copy.
- Retry must announce pending/result accessibly and retain existing edits on failure.
- Prevent affected mutations that overwrite unknown configuration.
- Parent handles all commits, pushes, PRs and Jira; implementer must not spawn agents.

## Review Focus

- Master failure with successful section/routes: unknown master, no false AI-off or enabled copy; confirmed routes still visible.
- Wiring failure with successful routing: route drafts usable, activation blocked; route failure with wiring success does the converse.
- Successful defaults/empty storage: show actual loader defaults, distinguish from unavailable; no invented incomplete stage data.
- Failed retry after unsaved edits: preserve draft, announce failure; successful retry reflects persisted values without falsely reporting success.
- Route resolution failure, missing credential fallback, and intentional master-off: distinct safe copy; no raw error string rendering.
