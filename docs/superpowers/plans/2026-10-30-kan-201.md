# KAN-201 saved Development setup implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Follow this plan task by task.

**Goal:** Owner-only creation and reopening of isolated experiment drafts with source snapshots and optional evaluator references.
**Architecture:** Reuse owner authorization, admin workspace selection, production document parsing, shared Postgres persistence and current admin UI patterns. Add experiment-owned tables; never run customer-mutating S0/S1 modules against customer workspaces.
**Tech Stack:** Next.js, TypeScript, Drizzle/Postgres, Zod, Vitest, Playwright.
**Spec:** [KAN-201](https://synapse21.atlassian.net/browse/KAN-201) and the approved [KAN-199 design](https://synapse21.atlassian.net/browse/KAN-199). Only setup slice; no generation/evaluation execution in this ticket.

## Global Constraints

- Use existing owner-console authorization on every experiment and document operation; enforce one selected source workspace and prevent customer-record/shared-setting mutation.
- Retain original and parsed source snapshots, ownership, content identity, parser identity/version and timestamps. Private development uploads do not enter customer workspaces.
- Gold references are explicitly evaluator-only, optional and section-specific. Missing/incompatible references do not prevent source generation; AI-parsed references remain provisional.
- Save and reopen drafts with validated inputs, clear upload status/errors and keyboard-accessible labelled controls. Introduce additive persistence only.
- No paid model calls in tests; reuse existing Vitest/Playwright test conventions and isolated test persistence.
- Publish to both remotes. PR target KAN-200 under ticket-specific agreed workflow. Leave PR open; no merge authorized by invoking skill.

## Review Focus

- Cross-workspace document IDs cannot escape the draft source workspace.
- Repeated or stale concurrent saves cannot overwrite newer draft state silently.
- Malformed/oversized uploads are rejected before parsing/persistence and parser failures remain actionable.
- Gold references remain separate from sources, preserving provisional review status and section compatibility.
- Authorization also covers document bytes and draft reopening, not just the page.
