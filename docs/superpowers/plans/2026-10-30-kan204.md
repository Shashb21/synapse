# KAN-204 evaluator configuration and scoring profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Let the owner version evaluation rubrics and independently evaluate immutable Development outputs.

**Architecture:** Extend `src/modules/development` and its owner API. Reuse immutable execution outputs, route resolution, database claims, existing parsing/validation, traced completions and scheduler delivery; do not rebuild stage algorithms or the human-reviewed benchmark scorer.

**Tech Stack:** Next.js 16, React, Zod, Drizzle/Postgres, Vitest, Playwright.

**Spec:** Jira KAN-204 (https://synapse21.atlassian.net/browse/KAN-204), approved KAN-199 design; ticket criteria reproduced below.

## Global Constraints

- Four sections: gap_extraction, tactic_extraction, matching_coverage, partial_splitting.
- Immutable balanced built-in profile, explicit 0–4 anchors, equal initial weights; editable criterion IDs/names/definitions/instructions/anchors/weights/optional thresholds, defaults and section overrides, Save As and immutable custom versions.
- Validate unique criterion IDs/names, finite bounded scores/thresholds, positive total weights and supported section/method combinations. Rubrics cannot override failed factual checks.
- Independent per-section evaluator route/settings and methods; snapshot full profile/config, source/output/reference original and parsed identities and review status.
- API/page evaluate and re-evaluate persisted immutable outputs without generation. Expected answers reach evaluators only. Historical scores never rewritten.
- Separate reference measures, deterministic factual checks, provisional AI assessments. Explicit semantic matching judgments, denominators, unscored empty denominators and absent/incompatible references. Never blend into pipeline accuracy or impersonate human review.
- Malformed or out-of-range replies explicitly fail evaluation while preserving generation. Durable attempts with trace/usage/cost accounting; uncertain sends never automatically retried.
- Owner authorization before I/O, bounded strict payload validation, isolated test persistence and scripted evaluators; no paid calls, customer mutations, shared routing changes, algorithm rewrites or new dependencies.
- Working branch and open PR target KAN-200 per ticket's specific agreed workflow. Parent integration and merges are outside this subtask.

## Review Focus

- Cross-experiment output/profile/reference IDs must fail before model dispatch.
- Concurrent version saves/evaluations cannot rewrite history or duplicate a send.
- Uncertain dispatch/recovery must retain evidence and avoid automatic charges.
- Invalid scores, duplicates, omitted criteria and unknown reference matches fail explicitly.
- Editor invalid numeric input and stale selected experiment/output must not silently save or evaluate another record.
