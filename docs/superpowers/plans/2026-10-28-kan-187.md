# KAN-187 Resumable Extraction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking.

**Goal:** Make source extraction explicitly complete or resumable beyond 80 blocks, without duplicate claims or overwriting human decisions.
**Architecture:** Keep existing extract modules and quote validator. Process one bounded page per request. Persist per-kind batch results and the associated claims atomically in a store-owned transaction; concurrent/retried requests reuse the winning result. Bind checkpoint identity to workspace, source, ordered block content snapshot, kinds and batch position as appropriate. UI holds continuation and offers progress/retry.
**Tech Stack:** Next.js, TypeScript, Drizzle/PostgreSQL, Vitest, Playwright.
**Spec:** https://synapse21.atlassian.net/browse/KAN-187 (acceptance criteria copied below).

## Global Constraints

- An 81-block fixture with its only extractable item in block 81 processes that item or clearly reports incomplete work with a working continuation.
- UI distinguishes complete, partial and failed extraction.
- Retries/resumption do not duplicate extracted claims or overwrite human decisions.
- Each bounded batch retains quote validation and workspace/source binding.
- Use the existing TypeScript repository's Vitest/database tests and browser tests where relevant.
- Preserve owner authorization, AI-off and provider-key gates. No unrelated refactors or dependencies.
- Work only in /private/tmp/synapse-kan187; user changes in the original checkout must remain untouched.
- Parent owns git commits, pushes and PR. Leave Jira In Review; do not merge or transition Done.

## Review Focus

- A later page must use only that page's source blocks; invalid/cross-source quotes remain rejected.
- Failures after one kind is saved retry safely without discarding success or duplicating it.
- Concurrent requests for the same page must commit at most one set of extracted claims.
- Edited/reordered parse blocks invalidate old continuation rather than skipping unseen content.
- UI must retain continuation and extraction kind on failure; refresh/restart can replay saved pages safely.
