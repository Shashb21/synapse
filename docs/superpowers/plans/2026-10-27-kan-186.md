# KAN-186 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Remove silent claim truncation and inconsistent Gantt save validation.
**Architecture:** SQL filtering precedes optional limits; one complete loaded claim set owns Gantt projection and final validation.
**Tech Stack:** TypeScript, Drizzle/PostgreSQL, Vitest.
**Spec:** docs/superpowers/specs/2026-10-27-kan-186-design.md

## Global Constraints

- Typed claim queries must filter by workspace and claim type in SQL before applying their limit.
- Existing callers keep the default limit of 200.
- Gantt projection must explicitly request all workspace claims, without a larger arbitrary cap.
- A final save must project activities, validate their tactic bindings, and derive snapshot tactic IDs, counts, and labels from the same loaded claim set.
- Active validated undated tactics continue to count in the snapshot; draft, rejected, and merged claims retain their existing behavior.
- Retain workspace isolation and existing error propagation and snapshot hashing.
- No UI or unrelated coverage-pair changes.

## Review Focus

- Newer gap claims cannot crowd older tactic claims out of a typed limited query.
- Other workspace claims cannot leak into typed or unlimited results.
- Older claims beyond 500 contribute activities and labels.
- Validated undated tactics remain in saved IDs and counts.
- Inactive or draft claims cannot become final activities.
