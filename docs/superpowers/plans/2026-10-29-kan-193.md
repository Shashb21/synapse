# KAN-193 AI availability implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Explain effective customer AI enablement, saved routes and credential readiness in the owner control panel.
**Architecture:** Existing control-panel server reads own known/unknown state. A compact read-only summary uses section/stage metadata and the existing resolver's permitted fallback semantics. Credential feedback accompanies draft selection and successful saves, without live calls.
**Tech Stack:** Next.js 16.3, React 19, TypeScript, Vitest, Playwright.
**Spec:** https://synapse21.atlassian.net/browse/KAN-193 (fetched 2026-10-29).

## Global Constraints

- Preserve copied KAN-109 UI improvements and original checkout changes.
- Preserve owner authorization, server-side validation, provider policy and API-key secrecy.
- Key presence means configured, not verified connectivity, quota, approval or a successful call.
- No key entry, OAuth reconnection or live provider calls.
- Missing primary credentials do not imply unavailable when a permitted configured fallback exists.
- Counts derive from AI_SECTIONS and model-stage metadata; ingestion is not a model route.
- Failed configuration reads remain unknown; no fabricated enabled/default/healthy state or leaked exception text.
- Keyboard/screen reader, light/dark, long labels and 390px must work.
- Parent handles commits, publication, PR and Jira; implementer must not spawn agents.

## Review Focus

- Master off preserves stored section preferences; master on/all sections off says customer AI not enabled.
- Ingestion-only enablement requires no model key; unavailable disabled stages must not make enabled ingestion blocked.
- Missing primary with permitted fallback is distinguished from no usable route; summary uses runtime resolver policy.
- Mixed provider/model routes are reported from model stages; bulk active-provider indication retains KAN-60 behavior.
- Partial read failures and refresh after save never imply health or retain misleading stale feedback.
