# KAN-195 AI switch save feedback

## Spec and design
Source: Jira KAN-195, retrieved 2026-10-29. Master and section controls need visible and screen-reader pending/success/error feedback without a confirmation gate. Existing POST actions return saved `ai` / `ai_sections`; server authorization and persistence remain authoritative. Keep existing control layout, 44px targets, focus and switch semantics. No invented actor/time; panel already renders persisted master metadata.

## Global Constraints
- Preserve one-click master and section actions; no dialog or reason requirement.
- `aria-checked` reports confirmed saved state, never an unconfirmed requested value.
- Immediately show and announce Saving; block duplicate requests per control, including repeated synchronous activation.
- Announce saved scope and state. Master On does not promise section/provider availability.
- Failed HTTP/network/malformed responses preserve confirmed state, give safe action-specific recovery copy and unlock retry. Never display raw infrastructure details.
- Master Off: all customers continue manual flows, saved section preferences persist, obvious turn-on through existing action/authorization.
- Actor/time only from persisted server data on refresh. Feedback stays associated with its control and cannot show stale success after a later change.
- Preserve unrelated work. No server authorization, provider policy, or API-key changes.
