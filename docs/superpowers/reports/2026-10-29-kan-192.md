# KAN-192: honest configuration state and recovery

The owner Control Panel reads master, section, route, wiring, identity, authorization, and route-resolution state independently. Failed reads carry no fallback value or exception text. Confirmed settings stay visible and usable; controls that depend on unknown saved data are disabled. Provider-key presence remains visible without exposing credentials.

Retry merges a fresh server response, announces pending and confirmed results accessibly, and retains route drafts when reads fail. Unexpected resolution errors use safe recovery copy; intentional AI-off and expected missing-provider/fallback states remain distinct. Runtime routing policy is unchanged. Earlier KAN-109 UI improvements were preserved; the original checkout was not edited.

## Decisions

- Resume existing copied KAN-109 improvements in an isolated worktree and use the explicitly requested native subagent workflow. The copied changes are included in the PR review; unrelated glossary/design notes are excluded.
